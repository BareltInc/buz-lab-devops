## Описание CI/CD процесса

Пайплайн настроен таким образом, чтобы гарантировать воспроизводимость и чистоту сборки:

1. **Сборка артефакта (`ci/build.sh`)**: 
   - Запускается в изолированном Docker-контейнере.
   - Устанавливаются зависимости, запускаются тесты.
   - Создаётся Python-артефакт (`.whl` файл), который сохраняется в папку `artifacts/`.
2. **Упаковка в образ**: 
   - `Dockerfile` настроен на сборку **из артефакта**, а не из исходных кодов (best practice).
3. **Деплой (`deploy/deploy.sh`)**:
   - Артефакт передаётся на сервер.
   - Собирается финальный Docker-образ.
   - Стек поднимается через `docker compose up -d`.

## Мониторинг

Настроен автоматический provisioning Grafana и Prometheus. При запуске стека дашборды и источники данных создаются автоматически.

Реализованные метрики:
1. **Health Check**: Статус доступности приложения (`up{job="app"}`).
2. **Посещения**: Количество HTTP-запросов к приложению за последний час (`sum(increase(http_requests_total[1h]))`).
3. **Ресурсы приложения**: Потребление CPU и оперативной памяти процессом Python (`process_cpu_seconds_total`, `process_resident_memory_bytes`).
4. **Ресурсы хоста**: Общая загрузка CPU и памяти сервера (через cAdvisor).

> **⚠️ Примечание по метрикам контейнеров**: 
> Метрики потребления ресурсов на уровне отдельных Docker-контейнеров (cAdvisor) могут агрегироваться или не отображаться детально из-за ограничений доступа к `cgroups` на уровне ядра предоставленного VPS-хостинга. Для гарантии стабильности используются метрики самого процесса приложения (`process_*`), которые работают корректно на любой инфраструктуре.

## Структура репозитория

```text
.
├── app/                    # Исходный код приложения
│   ├── myapp/              # Основной код Flask
│   ├── tests/              # Тесты
│   └── pyproject.toml      # Конфигурация сборки
├── ci/
│   └── build.sh            # Скрипт сборки артефакта
├── deploy/
│   └── deploy.sh           # Скрипт развертывания на сервере

│   ├── grafana/            # Provisioning дашбордов и datasource
│   └── prometheus.yml      # Конфигурация Prometheus
├── docker-compose.yml      # Описание стека контейнеров
├── Dockerfile              # Инструкция сборки образа из артефакта
```
